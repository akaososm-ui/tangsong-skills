# 输入与输出结构

## 1. 最小输入包

```markdown
【我的产品/服务】
- 名称：
- 解决什么问题：
- 交付什么结果：
- 适合谁：
- 不适合谁：

【目标客户】
- 具体身份：
- 当前处境：
- 高频问题：
- 想要的结果：

【本周业务目标】
- 本周重点产品/服务：
- 希望客户完成的下一步动作：
- 客户当前阶段：

【内容母体】
- 来源：分享 / 答疑 / 咨询 / 复盘 / 客户问题 / 已发布内容
- 原文或转写：

【可用 CTA】
- 动作：
- 真实承接方式：
- 资料、服务或入口：

【平台协议】
- 朋友圈：默认每天3条，可调整为
- 公众号：默认每周3篇，可调整为
- 短视频：默认每周3条，可调整为
```

历史内容、个人说明书、满意/不满意样稿是增强输入，不是替代产品、客户、业务目标和内容母体的材料。

## 2. 内容母体卡

```markdown
status: content_mother_ready

## 内容母体
- 标题：
- 来源与日期：
- source_type: user_owned / external_reference / mixed
- 原始问题或场景：
- 用户原话/事实：
- 核心判断：
- 支撑案例、证据或客户语言：
- 客户可以采取的动作：
- 对应产品/服务：
- 可承接的下一步动作：
- 可拆角度：
- 待补充/待核验/不可公开：
```

## 3. 7天内容矩阵

每一行是一个内容单元，不只是一个标题。默认矩阵应有 27 行：21 行朋友圈、3 行公众号、3 行短视频；如果用户调整数量，要记录调整后的总数和原因。

| 日序 | 平台 | 客户阶段 | 内容目的 | 主题/核心问题 | 母体来源 | 平台任务 | 平台适配理由 | 产品连接 | CTA | 反馈指标 |
|---|---|---|---|---|---|---|---|---|---|---|
| Day 1 | 朋友圈 |  |  |  |  |  |  |  |  |  |

内容目的可选：吸引正确的人、建立信任、教育客户、提供证据、处理顾虑、吸引客资、产品承接、推动行动。每条只选一个主目的。

默认节奏：朋友圈21条、公众号3篇、短视频3条。公众号和短视频不要求每天发布；矩阵中要写清实际发布日和内容任务。

## 4. 三平台样稿

每篇样稿前先写设定，不直接只交正文：

```markdown
status: draft_for_review

## 内容设定
- 平台：
- 内容单元：
- 目标客户：
- 客户阶段：
- 内容目的：
- 引用母体：
- 核心判断：
- 平台策略：
- CTA：
- 平台适配理由：

## 开头备选
1.
2.
3.

## 正文/大纲

## 事实与待确认项

## 用户修改区
```

## 5. 内容生成规则卡

```markdown
status: awaiting_rule_confirmation

## 稳定规则
- 开头：
- 叙述顺序：
- 句子和段落节奏：
- 场景、案例和客户语言：
- 朋友圈表达：
- 公众号表达：
- 短视频表达：
- CTA：

## 暂定规则

## 本次临时修改

## 禁用表达与结构

## 事实、隐私、版权和承诺边界

## 仍待确认
```

规则卡只有在用户明确确认后，才将状态更新为 `batch_confirmed_rule`。单独确认规则卡但未确认三个样稿，不能进入批量生成。

```markdown
## 内容单元

- 内容目的：
- 客户阶段：
- 母体来源：

- CTA：
- 正文：

### OA-01 公众号
- 发布日：
- 内容目的：
- 客户阶段：
- 母体来源：
- 平台适配理由：
- CTA：
- 标题/正文：

### V-01 短视频
- 发布日：
- 内容目的：
- 客户阶段：
- 母体来源：
- 平台适配理由：

```

批量输出后必须附：事实风险、重复内容、平台适配问题、CTA 承接风险和需要人工确认的清单。
