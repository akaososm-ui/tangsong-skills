# 产品痛点与解决方案：方法论参考

## 来源与用途

本文件是对用户提供的飞书课程《AI + 产品：如何把能力变成爆款产品》、本地销售与营销资料，以及本轮访谈决策的压缩整理。它服务于 Skill 的判断流程，不是销售话术，也不把课程中的案例当成普遍事实。

## 核心顺序

产品不是课程、社群、咨询或商品这些形式本身，而是帮助用户解决问题的一种方式。通用顺序是：

> 先理解真实问题 → 定义痛点 → 收敛优先客户 → 设计解决方案 → 明确交付与边界 → 对齐付费理由。

不能从产品形式倒推所有用户都需要它。产品想法必须回到具体用户、具体场景和具体改变。

## 什么才算痛点

痛点至少包含：

1. 发生在谁身上；
2. 在什么场景出现；
3. 用户做了什么、没做什么或反复失败什么；
4. 现有解决方式是什么；
5. 现有方式为什么不够；
6. 持续带来的时间、收入、机会、关系、身份或精力成本；
7. 用户为什么愿意现在处理。

“想变好”“焦虑”“想赚钱”是需求线索，不是完整痛点。要把它翻译成日常行为和具体损失，例如“每次成交都要临时解释服务，导致客户无法理解差异”，而不是“营销能力不足”。

### 痛点分层

- 表层：用户能直接说出的现象；
- 深层：表层问题对业务、生活或身份的影响；
- 极限场景：如果问题持续，可能造成的合理后果；
- 购买动机：用户真正愿意为哪一个改变付费。

极限场景是帮助理解紧迫性的推演，不是用来制造恐惧的文案。事实、合理推导和假设必须分开。

## 需求挖掘路径

可以循环使用：

> 了解现状 → 挖掘需求 → 发现问题 → 设计解决问题的方式。

提问应从产品能解决的问题倒推，但不能诱导用户只回答“是”。问题优先使用具体场景、行为、频率、过去尝试和实际成本。相似案例或典型场景可以帮助用户想起潜在问题，但案例必须明确是例子，不能冒充该用户事实。

用户的表层需求和深层需求可能不同。表层是“想减肥”，深层可能是进入亲密关系、恢复尊严或摆脱被评价；产品定义要先确认哪个改变是可交付、可承接的，不要无限延伸到人生所有问题。

## 客户角色

客户画像要至少回答：

- 谁使用；
- 谁从结果中受益；
- 谁影响购买；
- 谁最终付款或拍板。

四个角色可能是不同的人，也可能全部重合。企业或家庭场景尤其要避免把使用者当成最终决策人。优先客户不是“所有可能的人”，而是当前痛点最强、产品匹配度最高、卖方有能力接住的一类人。

## 产品形态判断

产品形态应由用户要获得的结果和交付机制决定：

- 要理解或获得方法：知识/信息型；
- 要借助专业判断或人工操作：专业服务型；
- 要得到独特、个性化的成品：定制制作型；
- 要直接获得一个物件或设备：实体商品型；
- 要使用系统、软件或自动化能力：数字工具型；
- 要获得一次现场经历或环境改变：体验/活动型；
- 要完成跨环节的整体改造：项目解决方案型；
- 要获得供给、渠道或关系连接：资源/撮合型。

现实产品常常是混合型。分析时写清“主产品 + 配套交付”，例如：智能家居全套打造 = 设备 + 空间设计 + 安装 + 售后；一对一疗愈 = 专业服务 + 定制方案 + 线下体验 + 后续跟踪。

## 付费理由与价格参考

用户购买的不是功能清单，而是问题被解决后的可感知改变。每个卖点都要对应一个痛点和付费理由。

价格可以从多个方向对照：用户预期、同类产品、交付范围、问题成本、交付时间、专业程度、风险和资源。AI 只能提出参考区间和不同价格下的交付差异，不能替用户最终定价，也不能在没有资料时声称完成同行调研。

## 产品定义的停止点

第一版完成到“产品可以被继续打磨、包装或交付设计”为止。不要在信息已经足够时继续追问，也不要自动进入访谈招募、预售、成交话术、渠道发布或市场验证。后续验证属于另一个阶段。
