# AI 协同阅读

## 定位

把“读完以后整理”升级为“阅读过程中的协作”。适用于值得认真读、需要理解和应用的书；消遣类阅读可以只做轻量记录。

核心目标不是生成漂亮摘要，而是让用户在读完每个重要部分时都完成一次：

- 看懂：知道作者在解决什么问题、如何论证。
- 想清楚：能用自己的话复述，指出疑问、联想和不同意之处。
- 用起来：把内容连接到真实问题、行动实验、内容、产品或业务。

## 工作流决策

先判断用户要做哪一种动作：

1. “我想读这本书”或“帮我规划” → 执行阅读初始化。
2. “我读完这一段/这一章了” → 执行阅读协作回合。
3. “这段看不懂/作者什么意思” → 先解释、举例、追问，不直接总结整本书。
4. “帮我消化/验收一下” → 执行理解验收。
5. “读完了，帮我沉淀/用起来” → 执行全书收束，再按需调用行动、方法论或业务融合技能。

若用户只是要微信读书个人划线的批量提取，继续使用 `$tangsong-weread-chapter-digest`；它是本技能的输入适配器，不承担完整阅读陪伴。

## 输入来源与来源协议

支持以下输入，不把微信读书当作前提：

| 来源 | 可接受材料 | 处理方式 |
| --- | --- | --- |
| 微信读书 | 书籍信息、目录、个人划线、想法 | 调用旧适配器或读取用户导出的内容 |
| 纸质书 | 拍照、扫描、页码、手写批注、口述 | OCR/转录后保留页码；图片不清时标记待确认 |
| 电子书 | 用户提供的 PDF、EPUB、Word、章节摘录 | 按目录和页码/章节定位；只处理用户提供或合法可用的内容 |
| 网页资料 | 作者公开文章、试读、访谈、公开章节、合法资料 | 标注 URL、访问日期和资料类型，不能把二手资料当原书原文 |
| 语音输入 | 用户对刚读内容的口述、疑问、联想 | 保存为用户理解材料，不改写成“书中观点” |

每条内容都要标注 provenance：

- `[原文]`：来自书或用户提供的原始材料。
- `[我的想法]`：用户的批注、联想、疑问、判断。
- `[AI解释]`：AI 为帮助理解而补充的说明或例子。
- `[待核验]`：无法确认出处、OCR 不清、资料不完整或存在争议的内容。

不要下载、拼接或输出完整的受版权保护书籍。网上资料只用于查找目录、背景或用户指定的合法章节材料；无法取得原文时，明确说明依据不足。

## 阶段一：阅读初始化

### 1. 判断阅读强度

把书归入一种主要模式：

- 主食：工具、方法、商业、职业类。目标是理解并做行动实验。
- 美食：文学、历史、哲学、社科类。目标是扩大视野、形成判断和感受，不强求立刻变现。
- 甜食：消遣、网文、轻小说。默认轻记录，不启动完整流程。
- 蔬果：百科、年鉴、报告、工具书。按问题查阅，不要求线性通读。

用户没有说明时，根据书名、阅读目的和当前问题做暂定判断，并把判断写进阅读任务单；不要把所有书都强制走重流程。

### 2. 建立阅读任务单

最少确认：书名、现有材料、阅读目的、当前问题、预期产出。缺少时只问影响路径的关键问题，允许用户先用“兴趣阅读”开始。

在书籍资料文件夹中创建或更新：`阅读任务单.md`。

内容包含：

```markdown
# 阅读任务单：<书名>

阅读模式：主食 / 美食 / 甜食 / 蔬果
阅读目的：
当前要解决的问题：
希望读完得到什么：
已有材料与来源：
阅读强度：轻量 / 标准 / 深度

## 预读地图
- 全书在解决什么问题：待读后修正
- 优先阅读部分：
- 可暂时跳过部分：
- 关键概念猜测：

## 阅读完成标准
- [ ] 我能用自己的话讲清核心主张
- [ ] 我能指出至少一个例子或证据
- [ ] 我能说明赞同、质疑或适用边界
- [ ] 我能决定一个下一步动作或明确“暂不应用”
```

如果有完整目录，先做“问题—章节”映射；没有目录时，不编造章节，先基于现有片段建立临时地图。

## 阶段二：边读边协作

一次协作回合只处理用户刚读完的一个自然单元：一段、一个小节、一章中的一组页码，或一次语音记录。不要一次替用户整理整本书。

用户可以只说“我读完了第 2 节”，也可以附上照片、摘录、PDF 片段、微信读书划线或语音。先识别材料边界；材料不足时说明“目前只能做局部理解”，不要补写原文。

每次协作按以下顺序：

1. **先接住用户理解**：如果用户已说自己的理解，先复述并区分“理解正确 / 需要修正 / 证据不足”。
2. **定位这部分**：它在全书或本章中要解决什么问题，和前后内容如何连接。
3. **拆解论证**：核心主张、理由/证据、案例、隐含前提、结论；区分作者原话与 AI 解释。
4. **解释难点**：用简单语言、一个贴近用户业务或生活的例子，必要时给出反例；不为了通俗而改变原意。
5. **调动海绵阅读九类记录**：自动识别阅读动机、核心概念、金句、故事案例、联想、问题、洞见、情绪、行动；只填有内容的类别，不制造空项。
6. **提出一个理解问题**：优先要求用户复述、举例、比较或应用，而不是继续输出更多文字。
7. **给出下一步建议**：继续读、重读、查背景、带着问题读下一节，或暂时跳过，并说明理由。

### 协作回合输出

写入同一书籍资料文件夹：`协作记录-<日期>-<章节或页码>.md`。

模板：

```markdown
# 协作记录：<书名> <章节/页码>

材料来源：
材料边界：
阅读时间：YYYY-MM-DD

## 我先这样理解
（用户原话；没有则写“用户尚未提供复述”）

## 这一部分在讲什么

## 论证链

## 关键概念与例子

## 我的问题 / 联想 / 情绪

## AI解释与待核验点

## 理解验收题

## 下一步阅读建议
```

对重要书，默认在每个自然单元后做一次轻量协作；不要等读完整本再第一次处理。

## 阶段三：理解验收

当用户说“帮我消化”“这一章读完了”或准备继续时，按阅读强度执行：

- 轻量：一句话复述 + 一个行动/感受。
- 标准：复述核心观点、举自己的例子、回答一个反事实或边界问题。
- 深度：重建论证图、比较相关经验/资料、指出证据质量和适用边界、设计行动实验。

如果用户答不出来，不把它判定为失败。继续采用“换句话说 → 换例子 → 对比反例 → 用户再复述”的循环，直到达到当前阅读完成标准，或明确记录为未理解问题。

## 阶段四：章节收束与全书收束

章节收束不是重复协作记录，而是形成可回看的理解卡：

- 本章要解决的问题
- 核心观点和论证链
- 最有价值的原文/案例及出处
- 用户真正形成的判断
- 仍未解决的问题
- 一个最小行动或暂不行动的理由
- 可以连接到哪些已有笔记或业务场景

全书收束只有在用户明确读完、暂停或要总结时执行。输出：

1. 这本书真正贡献了什么。
2. 哪些内容对用户当前问题有用，哪些只是背景。
3. 用户是否同意作者，为什么。
4. 书中方法的适用边界和可能误导。
5. 已完成、待验证、暂不采用的行动清单。
6. 值得进入方法论库、内容库、产品/交付资产的候选项。

不要把“AI 生成的好总结”当作用户已经掌握；只有用户复述、举例、应用或明确判断过的内容，才能标记为“已消化”。

## 文件落点与兼容关系

默认沿用现有目录，不新建平行知识库：

`01-输入/书籍资料/<书名>/` under the user's own Obsidian workspace.

建议文件序列：

- `00-书籍信息.md`
- `阅读任务单.md`
- `协作记录-<日期>-<章节或页码>.md`
- `理解卡-<章节或页码>.md`
- `全书收束.md`
- `行动清单-<章节>.md`
- `方法论候选-<章节>.md`
- `业务融合卡-<章节>.md`

后面三类文件继续交给现有下游技能处理，只有用户明确要求时才写入 `04-资产`。不覆盖用户已有记录；同名更新前先读取并保留原始内容，必要时创建版本或追加。

## 边界与质量检查

- 不把书外知识写成作者观点。
- 不把用户联想写成书中结论。
- 不为了凑齐模板生成空洞金句、行动或方法论。
- OCR、图片、网页摘要不完整时，标注缺口并请求更清晰材料。
- 重要书优先理解和验收，速度训练只作为辅助；不要用 321 阅读法压缩需要细读的论证。
- 任何方法进入长期资产前，区分“书中建议”“用户理解”“用户实际验证结果”。

## 相关技能

- `$tangsong-weread-chapter-digest`：只做微信读书个人划线/想法的输入提取。
- `$tangsong-book-action-converter`：把章节理解转成小行动。
- `$tangsong-book-methodology-distiller`：筛选可复用的方法论。
- `$tangsong-book-business-integrator`：连接 AI 提效商业私教、内容、产品和交付。
