# OPC Offline Event Methodology

## Core Frame

An OPC offline event is a high-trust field inside a conversion chain:

```text
backend product -> front-end user problem -> offline topic -> onsite result ->承接 action -> follow-up conversion
```

Do not treat offline events as proof of influence, photo opportunities, or one-off sharing sessions.

The event must answer three questions:

1. Where do people come from?
2. What do participants get onsite?
3. Where do they go after the event?

## Four Stages

### 1. Preparation

Clarify:

- backend product or next-step offer
- target user
- front-end problem
- onsite result
- venue and constraints
- recruitment source
- budget and break-even logic
- follow-up path

Output:

- activity strategy sheet
- target and unsuitable audience
- topic and hook
- backend承接 path
- rough agenda
- registration questionnaire
- recruitment and poster copy direction
- operation timeline

### 2. Recruitment

Recruitment is not "posting a poster"; it is screening users with real demand.

Copy should answer:

- why attend
- what problem is solved
- what the onsite result is
- who is suitable
- who is unsuitable
- what to prepare
- what happens after registration

Offline events should usually have a price, deposit, application, preparation task, or other threshold. Free events are possible, but the organizer must know how costs and follow-up conversion are handled.

### 3. Onsite Delivery

Do not simply move an online class offline.

Offline value comes from:

- real connection
- live energy
- interaction
- diagnosis
- demonstration
- practice
- being seen and responded to

Standard structure:

1. Check-in and warm-up.
2. Self-introduction using a problem template.
3. Shared frame or core method.
4. Case/demo.
5. Participant practice.
6. Q&A or case teardown.
7. 7-day action plan.
8.承接 action.

### 4. Conversion and Follow-Up

The event does not end at the group photo. The 24-72 hours after the event are the key window.

Actions:

- thank-you message
- selected photos
- feedback questionnaire
- recap prompt
- material pack
- user segmentation
- private follow-up
- next-event invitation
- consultation or product application
- organizer recap

Segment users into A/B/C/D:

- A: high fit, clear pain, active interaction, budget or urgency.
- B: interested but early-stage.
- C: relationship or observation users.
- D: low-fit users.

## AI's Role

AI helps turn a messy event idea into a project system:

- topic options and risk checks
- copy variants
- questionnaire fields
- project plan
- material checklist
- questionnaire analysis
- onsite agenda
- host script
- talk and PPT outline
- group operation messages
- follow-up scripts
- recap and assetization

AI should not decide:

- whether the backend product is real
- whether the audience can pay
- whether promises are appropriate
- final public copy
- partner and lead ownership boundaries
- sensitive privacy choices

## Public Case Reference Rules

The organizer's public activities can be used as teaching cases, but they are examples rather than permanent facts or guaranteed results. Only use information that is public or explicitly supplied by the organizer.

Useful case fields:

- event background and business goal
- target audience and front-end problem
- topic and onsite mechanism
- participant output
- backend or next-step handoff
- follow-up action and verified result
- reusable judgment
- conditions where the case should not be copied

Example public cases:

- 2026-07-05 AI one-person-company offline event: validated that users do not only need tools; they need to connect AI to business workflows.
- 2026-07-25 Codex x AI knowledge base event: validated that knowledge IPs often have content materials but lack a callable knowledge system; also showed the need to screen participant stage and tool readiness more clearly.

These examples must not be used to claim a guaranteed attendance, revenue, conversion rate, or participant result. If a fact is not verified, mark it `【待核验】`.

Reusable lesson:

> Wanting to join an AI offline event is not the same as being ready for a deep hands-on AI workshop.

## Common Mistakes

- Start by designing a poster before clarifying conversion.
- Pick a broad topic that gives users no reason to come offline.
- Ignore recruitment source and assume people will show up.
- Make the whole event a speech with no participant output.
- Forget privacy, photo consent, recording, and feedback collection.
- End at group photo without 24-72 hour follow-up.
- Let AI generate many documents without a clear human strategy.

## First-Event Safety Net

For a first-time organizer, the plan must include:

- one clear primary goal rather than several equal goals
- one visible participant output that can be completed onsite
- a small enough attendance target for the organizer's actual capacity
- a named owner for recruitment, venue, onsite delivery, and follow-up
- a T-minus checklist and a same-day fallback
- a consent decision for photos, recording, testimonials, and public reuse
- a follow-up list that can be acted on within 24-72 hours
