# Knowledge Base Daily Lesson Example

This reference captures the real edit pattern from Tang Song's knowledge-base daily lesson.

Use it when revising:

- 社群日课;
- tool tutorials;
- knowledge-base / Obsidian articles;
- AI one-person-company content;
- education content that should sound like Tang Song speaking from work, not like an AI explainer.

## Context

Original topic:

Tang Song wanted to write a daily lesson about building a personal knowledge base, especially for content creators and knowledge-intensive workers. The central metaphor was a home wardrobe: it stores clothes, socks, pants, and seasonal items that are not always used today, but must be kept, sorted, and retrievable.

Core ideas to preserve:

- A knowledge base is not only a folder of documents.
- It stores text, images, resources, plans, reports, PPTs, summaries, course notes, reading notes, social posts, image materials, and script drafts.
- For AI one-person companies and content creators, the knowledge base is where daily sharing, project thinking, and content assets accumulate.
- The useful logic is not "collect everything"; it is letting material flow through a lifecycle: collect -> organize -> retrieve -> reuse -> update.

## V1 Problems

The first rewritten version was usable, but still had AI traces:

- Some sentences were too complete and polished.
- Several paragraphs ended with summary-style conclusions.
- The structure had visible "three-point" rhythm.
- Some phrasing sounded like a method article rather than a person speaking after actually sorting their own Obsidian vault.
- The tone occasionally became too abstract: "知识库不只是..." or "真正要做的是..." appeared as polished lesson endings.

## V2 Direction

The better version moved toward:

- first-person recent action: "这两天我一直在整理自己的 Obsidian 知识库";
- reader pain: "不是没积累, 是临到要用的时候想不起来";
- concrete categories from real work: 方案、项目报告、PPT、复盘、朋友圈、图文、视频稿、配图、课程笔记、读书笔记;
- process language: 入口、分类、复用、更新;
- practical ending: start with a small wardrobe that can flow, not a perfect system.

## Targeted Edits That Worked

### 1. Replace Polished Diagnosis With Human Scene

Before:

```text
不是因为你没有积累，而是因为你想不起来自己积累过什么。
```

After:

```text
你明明有积累，但临到要用的时候，脑子里就是一片空。
```

Why:

The second sentence sounds closer to the real moment when someone needs to write, deliver, or make a plan and cannot retrieve old material.

### 2. Break A Neat List Into Work-Like Thinking

Before:

```text
哪些地方有观点，哪些地方有客户原话，哪些地方能拆成案例，哪些地方以后可能变成内容选题。
```

After:

```text
有没有能用的观点，有没有特别像客户原话的句子，能不能拆出一个小案例。顺手也看看，这里面有没有以后可以变成选题的东西。
```

Why:

The second version feels like a person checking material while working. It keeps the same meaning, but the rhythm is less machine-like.

### 3. Lower The Abstract Payoff

Before:

```text
这样跑几轮之后，知识库就不只是一个存资料的地方了。它会慢慢变成一个能支持你判断、表达和交付的工作系统。
```

After:

```text
跑过几轮之后，你会发现它开始帮你干活了。不是那种很神奇的干活，就是你要写东西、做方案、准备课程的时候，终于有东西可以翻出来用。
```

Why:

The phrase "工作系统" can be correct, but too easy to sound like an AI conclusion. The rewrite brings the value back to具体工作.

### 4. Replace Numbered Pits With Natural Warnings

Before:

```text
第一个坑...
第二个坑...
第三个坑...
```

After:

```text
最容易卡住的地方...
还有一种情况...
更隐蔽的问题...
```

Why:

The article still has structure, but it no longer feels like a generated checklist.

### 5. End Small

Before:

```text
你真正要做的是...
```

After:

```text
重点是别让这些东西散掉。

先搭一个能流动的小衣柜，够了。
```

Why:

The final version keeps the wardrobe metaphor and leaves the reader with a concrete, doable action. It avoids a motivational grand finale.

## Pattern To Reuse

When a Tang Song daily lesson feels AI-written, do not merely replace words. Check whether the article has:

- a real starting point;
- a concrete reader problem;
- examples from work;
- visible reuse path;
- one small action at the end.

If these are missing, add them from the provided material. If the user did not provide the real detail, do not invent it.
