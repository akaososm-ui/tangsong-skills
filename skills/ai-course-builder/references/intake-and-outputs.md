# Course brief and output templates

Use this reference when the user needs a structured intake or a defined deliverable. Do not complete fields by guessing.

## 1. Course brief

```text
[Format]
Single session / workshop / cohort / recorded course / curriculum:

[Learners]
Actual audience:
Current stage:
Prerequisites:
Reachable group:

[Problem]
What do they repeatedly ask or struggle with:
What have they already tried:
Why did those attempts not solve it:

[Result]
What must they complete, produce, decide, or change:
How will the result be checked:
What will not be promised:

[Instructor]
Relevant background:
Real experience:
Judgment criteria:
Cases and evidence:
Claims or cases that must remain private or unverified:

[Direction]
Topic or working title:
Delivery context:
Learning or business goal:
Content boundary:

[Materials]
Recordings / consultation notes / prior lessons / articles / learner questions /
templates / demonstrations / links:

[Constraints]
Duration:
Group size:
Tools and equipment:
Delivery mode:
Copyright, privacy, and accessibility requirements:
Requested output location and format:
```

If essential fields are missing, return the incomplete fields and confirmation questions instead of a full course plan.

## 2. Single-session output

1. Course title and one-sentence position
2. Learner profile, prerequisites, and real problem
3. End result and non-promised boundary
4. Time plan
5. Teaching path
6. Case or demonstration script
7. Live exercise and success sample
8. Common errors and troubleshooting
9. Q&A and escalation boundary
10. Next action and feedback route
11. Learner handout or worksheet
12. Retrospective and assetization checklist

## 3. Curriculum output

1. Final result and completion artifact
2. Target and unsuitable learners
3. Prerequisites
4. Milestones
5. Module map
6. Lesson objectives, actions, and outputs
7. Assignment, feedback, and Q&A rhythm
8. Completion risks and recovery paths
9. Tool, material, and version boundaries
10. Completion acceptance criteria
11. Follow-on learning or service path
12. Retrospective, updates, and automation candidates

## 4. Lesson or module unit

| Field | Required content |
|---|---|
| Learner problem | The concrete obstacle this unit addresses |
| Observable result | What learners finish by the end |
| Instructor judgment | The judgment learners must understand |
| Situation/case | A real and authorized context that makes it understandable |
| Teaching path | Where the explanation starts and how it progresses |
| Learner action | What learners do during or after the lesson |
| Check method | How to tell whether it is done correctly |
| Common error | Where learners are likely to get stuck |
| Artifact | File, screenshot, decision, process, or work product left behind |
| Provenance | Instructor experience, external source, or unverified hypothesis |
| Human confirmation | What the instructor must approve |
