# 唐宋爆款内容拆解

这是一个“先取证、再拆解、后沉淀”的内容研究 Skill。它不是洗稿工具，也不是自动写作工具。默认输出一份可复核的内容拆解卡，并把结果写入固定本地知识库。

## 固定输出位置

默认输出到当前 Obsidian Vault 下：

```text
02-处理/爆款内容拆解库/
```

本次用户明确指定本地路径时，使用用户指定路径；没有指定时不要每次重新询问。若当前工作目录不是唐宋 Vault、且无法定位 `02-处理`，只询问一次本地输出根目录，再开始写入。

第一次写入时创建目录，并维护根目录下的 `00-索引.md`。每条内容一份独立 Markdown，不覆盖已有文件；相同内容再次运行时先读取旧文件，做增量补充。

在线输出不是默认路径。只有用户明确要求保存到飞书文档/文件夹时，才调用 `lark-doc` 或 `lark-drive`；在线输出仍要保留本地拆解文件作为稳定副本。没有用户授权时，不创建、修改或分享飞书文档。

## 核心边界

- 默认只做拆解，不写仿作、脚本、标题改写或发布文案。
- 原文、页面数据、字幕、转写和截图属于证据；观察、推断和待验证假设必须分开。
- 不把一次爆款推断为稳定规律，不补造粉丝量、点赞量、评论反馈、商业结果或作者经历。
- 原作者的表达、案例和人设不能复制；只提取结构、机制、形式和迁移条件。
- 如果评论区、粉丝量或商业路径无法读取，明确写“未验证”，不要用常识代替。
- 采集失败时必须让用户提供原始信息；不能用标题、搜索摘要、相近笔记或模型常识补齐正文。
- 正式拆解前必须取得用户的业务情况和本次想写的内容方向；缺任一项时停在信息收集，不进入七层拆解，也不写入长期库。

## 0. 入场门槛与停止条件

正式拆解必须同时满足三类输入：

### A. 原始内容材料

至少取得一种足以复核内容结构的原始材料：完整网页正文、完整本地 Markdown/Word/PDF、完整视频/音频文件、完整转写、可读的连续截图，或用户直接粘贴的全文。链接本身、标题、摘要、搜索结果和他人的概括不算原始内容。

### B. 用户业务情况

至少明确：

- 你是谁/目前的定位是什么；
- 服务或产品是什么，解决谁的什么问题；
- 目标客户是谁；
- 主要变现方式或希望承接的后端路径；
- 当前最想通过内容获得什么结果：获客、建立信任、销售、交付或其他。

### C. 本次想写的内容方向

至少明确：

- 想写的主题、问题或暂定标题；
- 准备发布的平台和内容形式；
- 这次内容想触达的人群；
- 期望读者看完后的动作或结果；
- 希望从样本中重点借鉴什么：选题、开头、结构、表达、案例、转化或其他。

### 硬性停点

- 内置 Browser/Chrome、GetNote、Feishu 或本地检索无法取得原始内容时：说明已经尝试的采集方式，停止拆解，请用户提供上述任一种原始材料。
- 只有标题、摘要、局部截图或相近内容时：不得做标题级拆解、不得推断正文、不得创建“完整拆解”文件；最多在对话中列出缺口，等待用户补源。
- 原始内容已取得，但业务情况或内容方向缺失时：只发送一次信息采集卡，停止拆解和写库。
- 粉丝量、互动数据、评论或作者商业路径缺失不阻断拆解，但必须标记“未验证”；它们属于可选证据，不得假造。

## 工作流

### 1. 先解决输入来源，不重复采集

按以下优先级读取已有信息：

1. 用户已经提供的本地 Markdown、视频、音频、截图、转写或分析文件。
2. 用户明确给出的 GetNote 笔记、Feishu 文档/文件夹或其他在线采集结果。
3. 当前对话中已经出现的原文、摘要、页面截图和数据。
4. 用户给出的原始链接，再用 Browser/Chrome 跟随跳转获取页面信息。
5. 页面无法解析时，才尝试下载视频、提取音频、语音转写和抽取关键帧。

如果已经存在完整转写或 GetNote 原文，不要再次用摘要代替原文，也不要重复下载。若来源只有摘要，要标记“只有摘要，未取得原文”。

如果所有内置方式都无法取得完整原始内容，执行“硬性停点”：告诉用户页面/工具无法读取，列出可接受的补源方式（粘贴全文、上传视频/音频、提供完整转写、提供连续截图、提供本地文件路径），然后等待用户补充。不要把失败的采集记录当成拆解结果写入固定库。

可接受的输入包括：抖音/小红书/公众号/视频号链接、GetNote 笔记 ID 或链接、Feishu 文档/文件夹、Obsidian 路径、Markdown/Word/PDF/网页文字、用户粘贴的原文、视频/音频文件、截图和手工记录。

链接只有在页面可读并取得正文/媒体内容后才算有效输入；“有链接但打不开”不等于“已取得内容”。

### 媒体类型分流

底层逻辑不因媒体类型改变，但“表达与证据”字段要切换：

| 类型 | 必拆证据 | 不必强行拆的字段 |
|---|---|---|
| 文字/长文/图文 | 标题、封面、开头、段落功能、分论点、案例/权威、金句、版式、CTA、评论/收藏 | 口播、机位、音频节奏 |
| 视频/口播 | 标题、首帧、前 2 秒、口播节奏、字幕、镜头、画面变化、章节、评论 | 文章版式 |
| 音频/播客 | 标题、开场、说话人关系、提问链、故事/观点节奏、转写结构、结尾行动 | 画面、封面细节 |
| 图片/海报/截图 | 图片文字 OCR、视觉层级、版式、信息密度、配文、评论/收藏 | 口播、段落节奏 |

文字内容要重点回答：标题如何命题、第一段如何让读者继续、段落如何推进论证、哪里加入案例/权威/金句、哪些地方降低理解成本、结尾如何导流或完成价值收束。图文内容还要记录封面与正文的分工。

### 2. 记录采集状态

在分析前先建立来源清单：

| 字段 | 内容 |
|---|---|
| 内容类型 | 文字/图文/视频/音频/图片 |
| 平台 | 抖音/小红书/公众号/视频号/其他 |
| 原始链接 | 页面最终 URL，不只保留短链 |
| 内容标题 | 页面标题或原文标题 |
| 作者与粉丝量 | 已验证/未知 |
| 可见数据 | 点赞、收藏、评论、转发、阅读、发布时间 |
| 原文状态 | 完整原文/完整转写/摘要/截图/未取得 |
| 视觉状态 | 已抽帧/已读版式/只看首帧/未取得 |
| 评论状态 | 已读取/页面不展示/需要登录/未尝试 |
| 采集来源 | 本地/对话/GetNote/Feishu/Browser/下载 |

页面直接可读时，优先保留页面提供的章节、时间、作者信息、互动数据和最终跳转 URL。文字页面优先读取正文、标题层级、图片文字、作者信息和评论；不要只使用搜索摘要。视频可播放时，至少抽取首帧、开头、中段、方法段和结尾关键帧；没有视频文件时，使用 Browser 截图并说明限制。

### 2.1 记录用户业务与本次内容方向

在进入样本判断前，先建立以下上下文；缺失时停止，不用模型记忆补全：

| 字段 | 用户提供的信息 |
|---|---|
| 当前定位 |  |
| 产品/服务 |  |
| 目标客户 |  |
| 变现路径 |  |
| 本次内容主题/暂定标题 |  |
| 发布平台与形式 |  |
| 想触达的人群 |  |
| 期望动作/业务结果 |  |
| 希望重点借鉴的维度 |  |

拆解时必须用这份上下文判断“人群是否值得学、业务是否值得学、哪些结构能迁移”，不能只给脱离业务的通用分析。

### 3. 判断样本是否值得拆

只有在“原始内容材料 + 用户业务情况 + 本次内容方向”三项均已通过入场检查后，才执行本节。缺少互动数据不阻断，但要把数据结论写成“未验证”。

先给四个结论，不要先写正文：

- **数据值得拆**：
  - 抖音 10 万粉以内：点赞 1 万以上进入研究池。
  - 小博主至少 1 万点赞；大博主通常要 20 万点赞以上，才称超级爆款。
  - 公众号看作者近期文章的相对异常值；小红书看低粉账号的异常高赞、高藏、高评、高阅组合。
- **人群值得学**：目标用户是否相通，不要求同赛道。
- **业务值得学**：作者的广告/带货/课程/咨询/陪跑等变现路径是否与用户相近。
- **只适合学表达**：数据或人群不匹配，但标题、首帧、口播、结构或视觉有学习价值。

如果缺少必要数据，只能写“数据未验证”，不能把内容直接称作爆款。大博主的粉丝惯性、偶发热点和平台红利要单独标注。

### 4. 按七层完成拆解

```text
样本判断
  → 人群与场景
  → 传播机制
  → 内容结构
  → 表达与媒体证据
  → 个人经验与可信度
  → 商业路径
  → 可迁移假设
```

#### 第一层：样本判断

说明为什么选它、数据是绝对值还是相对异常值、哪些信息还未知。

#### 第二层：人群与场景

写清谁会被击中、在什么时刻刷到、他正在经历什么、想得到什么。优先引用原文中的用户语言和具体场景。

#### 第三层：传播机制

从即时满足、社交认同、猎奇/信息差、情绪宣泄、自我提升中选 1-2 个主机制，并给出原文或画面证据。

#### 第四层：内容结构

按功能切段，不按自然段抄写。可使用：钩子前置、痛点引入、身份背书、提出观点、重新定义、引入解决方案、核心理论、分论点、案例、权威、金句、个人故事、作者做法、清单、CTA、感召升华。

每段至少回答：这一段完成什么、为什么放在这里、如何把用户推向下一段。

#### 第五层：表达与媒体证据

同时分析：

- 标题：关键词、冲突、结果承诺、人群指向。
- 封面/首帧：画面主体、文字层级、颜色、首屏信息量、是否 2 秒内明白；文字内容要同时看封面和正文的分工。
- 文字表达：第一段的进入方式、标题与小标题、段落长短、论证递进、案例/权威/金句密度、结尾 CTA。
- 口播：开头速度、停顿、问句、重复、金句、案例密度、章节节奏。
- 画面：机位、景别、场景切换、B-roll、字幕位置和视觉变化。
- 音频/播客：开场抓力、提问链、说话人关系、故事与观点的比例、听觉记忆点。
- 数据/评论：点赞、收藏、转发、评论和评论正文是否已经验证。

#### 第六层：个人经验与可信度

区分身份、个人经历、过程证据、案例、权威、数据和情绪表达分别承担什么作用。没有证据时不要把强语气当成事实证明。

#### 第七层：商业路径与迁移

分析内容吸引什么人、是否导向作者产品/服务、前端人群是否与后端匹配。最后分成：可直接学习的结构、需要换成人群语言的部分、不能照搬的前提、待验证假设。

### 5. AI 辅助和人工停止点

如果使用 AI 对已有原文进行二次拆解，要求 AI：

1. 先输出事实、未知信息和推断，不直接写结论。
2. 按段生成“原文摘要 / 功能标签 / 段落作用 / 与下一段关系”。
3. 按媒体类型列证据：文字拆标题、开头、段落、版式和 CTA；视频拆首帧、口播、画面和字幕；音频拆开场、提问链和转写结构；图片拆 OCR 和视觉层级。
4. 不把作者业务结果等同于内容结构效果。
5. 不进入写作，除非用户明确说“进入写作阶段”。

AI 只负责整理已取得的原始材料和用户已提供的业务上下文；不能替用户补写业务定位、内容目标或缺失的原文。

老师必须确认：样本是否值得拆、主机制是否成立、迁移条件是否成立。未确认的拆解只能标记为“初稿”，不能进入长期方法论。

### 6. 写入固定本地库

文件命名优先：

```text
YYYY-MM-DD｜平台｜作者｜标题短名.md
```

文件内必须包含：来源信息、样本判断、传播机制、结构拆解、标题/开头/首帧、与媒体类型对应的表达证据、可信度、业务路径、可迁移点、不能照搬点、待验证项和采集限制。

写入后更新 `00-索引.md`，至少记录日期、平台、作者、标题、内容类型、数据判断、主要机制、业务匹配度和文件链接。

未通过入场门槛时，不创建完整拆解文件、不更新索引；如用户明确要求保留采集缺口，才另建“待补原始材料”记录，并明确它不是拆解结果。

### 7. 验收

- [ ] 已读取已有采集信息，再决定是否补采集。
- [ ] 已保留最终 URL 和来源类型。
- [ ] 已取得可复核的原始内容；采集失败时已停下并索要原始信息。
- [ ] 已取得用户业务情况和本次想写的内容方向。
- [ ] 数据事实、观察、推断和假设已分开。
- [ ] 已说明原文、转写、画面和评论的可得程度。
- [ ] 已完成七层拆解，不只分析标题。
- [ ] 已明确“值得学什么”和“不能照搬什么”。
- [ ] 已写入固定本地文件夹并更新索引。
- [ ] 没有未经授权生成仿写或发布稿。

## 默认完成报告

最终只需报告：采集到什么、用户业务与本次内容方向是什么、写入哪个文件、哪些信息已验证、哪些仍缺失、是否生成了写作内容。若触发停止条件，只报告缺什么以及用户可提供什么，不创建完整拆解文件。不要把临时下载文件当成长期资产；长期资产是本地拆解 Markdown 和索引。
