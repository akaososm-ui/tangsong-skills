# 唐宋知识库框架搭建

## Overview

Build a knowledge base as a usable closet, not as a decorative archive. The goal is to let past writing, projects, cases, notes, client questions, prompts, and reviews participate in today's work.

Use this skill to guide the user step by step. Do not output a complex folder tree before understanding the user's business, materials, and output goals.

## Core Theory

Treat the knowledge base as a flow system:

- Raw materials enter.
- Useful parts are cleaned and distilled.
- Outputs are produced.
- Reusable methods, cases, templates, and claims become assets.
- Prompts, skills, and workflows become tools.
- Reviews calibrate future decisions.

Do not start with theme-based classification. Start by identifying the current stage of each material.

Use this staged structure:

- `00-系统管理`: rules for naming, routing, folder use, and maintenance.
- `01-输入`: raw unprocessed materials.
- `02-处理`: materials being cleaned, summarized, distilled, or decomposed.
- `03-输出`: publishable or deliverable outputs.
- `04-资产`: reusable methods, SOPs, templates, cases, user quotes, claims, examples, and standards.
- `05-工具`: prompts, AI Skills, workflows, scripts, templates, and automation instructions.
- `06-复盘`: daily reviews, project reviews, content data reviews, event reviews, and decision calibration.
- `99-归档`: old projects and inactive materials that should not stay in the active workflow.

If the user is just starting, begin with only:

- `01-输入`
- `02-处理`
- `03-输出`
- `04-资产`

Add the other folders only when the user has enough materials or a clear operating need.

## Operating Rules

- Ask before designing.
- Ask at most 3 questions per round.
- Do not invent the user's business, experience, clients, cases, or materials.
- Prefer a minimal usable framework over a complete system.
- If the user's answer is scattered, summarize it and ask for confirmation.
- If a material's stage is unclear, place it in `01-输入` or `02-处理`, not `04-资产`.
- Treat original transcripts, screenshots, chat records, rough notes, and recordings as raw input.
- Treat stable methods, repeated answers, SOPs, templates, proven cases, reusable claims, user language, and judgment criteria as assets.
- Always connect the knowledge base to a real output: article, post, short video script, course outline, consulting deliverable, sales material, community share, or workflow.
- Write in Chinese by default when the user writes in Chinese.

## Workflow

### 1. Understand the User

Ask only these 3 questions first:

1. What business, project, or role are you currently working on?
2. What type of content or deliverable do you most want to produce consistently?
3. What is your biggest bottleneck in content creation or knowledge output?

After the user answers, briefly summarize:

- current business or role
- main output goal
- current bottleneck
- what the knowledge base should optimize for

### 2. Inventory Existing Materials

Ask the user to list 10-20 existing materials. Accept rough descriptions; do not require perfect file names.

Useful material types:

- articles, newsletters, blog posts
- Xiaohongshu posts, video scripts, social posts
- course notes, lessons, PPTs, training materials
- consulting records, client cases, delivery notes
- user questions, comments, DMs, chat records
- community shares, live transcripts, recordings
- personal notes, reviews, ideas, screenshots
- SOPs, prompts, templates, workflows

If the user has too many materials, ask them to choose the 10 most recent or most commercially relevant ones first.

### 3. Classify by Stage

Classify each material into the staged structure.

Use this table:

```markdown
| Material | Stage | Why | Next Action |
|---|---|---|---|
```

Classification guidance:

- Use `01-输入` for material that has not been cleaned or interpreted.
- Use `02-处理` for material that contains useful information but still needs extraction, summarization, or restructuring.
- Use `03-输出` for material that can be published, sent, taught, or delivered directly.
- Use `04-资产` only for material that can be reused many times across future content, products, or delivery.
- Use `05-工具` for prompts, reusable AI instructions, skills, workflows, templates, or automation.
- Use `06-复盘` for records that explain what happened, what worked, what failed, or what should change.
- Use `99-归档` for inactive material that should be preserved but not kept in the active workflow.

### 4. Design the Minimal Framework

Create a folder structure suitable for the user's current stage.

For each folder, include:

- what goes here
- what does not go here
- examples from the user's own materials
- the next action

Keep the folder tree shallow. Do not create detailed topic subfolders unless the user already has enough volume and a repeated retrieval need.

### 5. Create the First Action Plan

Output:

1. first 10 materials to collect into `01-输入`
2. first 3 materials to process
3. assets that may be extracted into `04-资产`
4. outputs that can be produced into `03-输出`
5. a 7-day action plan

The 7-day plan should be lightweight enough that the user can actually execute it.

### 6. Turn the Knowledge Base Into Output

Based on selected processed materials, generate a first content/output entry when useful:

- 10 content topics
- one article outline
- one social post
- one Xiaohongshu post structure
- one short video script
- one community share
- one consulting or course delivery asset

Keep the user's real experience and judgment. Do not write generic AI content.

## Output Format

For a complete run, use this structure:

```markdown
# 你的最小可用知识库框架

## 1. 当前业务和内容目标

## 2. 你的材料盘点

## 3. 阶段判断表

| 材料 | 当前阶段 | 为什么 | 下一步 |
|---|---|---|---|

## 4. 文件夹结构

## 5. 第一批要整理的材料

## 6. 第一批可产出的内容

## 7. 未来 7 天行动计划
```

For a live workshop or classroom setting, use a shorter task-card structure:

```markdown
# 我的知识库小衣柜

## 1. 我现在最想稳定产出的内容

## 2. 我手里已有的 10 条材料

## 3. 这些材料现在分别处在哪个阶段

## 4. 我第一批最该处理的 3 条材料

## 5. 我这周先产出的 1 个内容

## 6. 我需要 AI 帮我做的第一步
```

## Avoid

- Do not build a complex taxonomy first.
- Do not overuse tags, backlinks, plugins, or automation.
- Do not classify everything into assets.
- Do not make a generic creator knowledge base.
- Do not ignore the user's actual output goal.
- Do not treat tools as the main point.
- Do not use vague labels such as `资料`, `灵感`, or `杂项` as the whole framework.
- Do not promise that the knowledge base can automatically solve business problems without user material and judgment.
